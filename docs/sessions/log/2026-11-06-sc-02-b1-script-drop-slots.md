# 2026-11-06 — SC-02 b1, le script déposé emplacement par emplacement (API) — done

Fait : migration 0123 (état `filling` d'un dépôt de script, `slot_key`, bornes de durée et `replaced_at` sur les fichiers, place et emplacement uniques parmi les fichiers vivants, politique `creator_replace` et droit de mise à jour limité à `replaced_at`/`updated_at` ; `team_insert` des demandes exige une version figée de la structure nommée). Contrats : `scriptSlots` (chaque série d'une étape en entier), `slotFileRefusal`, `slotLengths`, `slotDurationRefusal`, `ScriptDrop`. Routes créatrice `POST /creator-space/content/script-drops`, `GET …/:dropId`, `PUT …/:dropId/slots/:slotKey`, `POST …/:dropId/submit`. Un fichier remplacé garde sa position, sort du dépôt et de ses envois, et son original s'efface comme celui d'un dépôt retiré. La durée d'une vidéo ou d'un vocal se vérifie sur le fichier nettoyé. Une demande de script faite à la main fige sa version (`structures.freeze`, après le contrôle de la structure). Tests : unitaires (emplacements, refus par type et par durée, emplacements manquants) ; intégration (début, reprise, remplissage, remplacement, envoi refusé puis accepté, version figée, original d'un fichier remplacé effacé).
Pas fait : lot b2 (parcours dans la PWA, cartons d'une version figée lus par la créatrice, captures) ; rappels de l'ADR 0055 § 4 ; écran d'agence de la cadence.
Décisions : un fichier remplacé garde sa ligne plutôt qu'un état de plus, pour que l'effacement retrouve son original. Un fichier encore en route compte pour « Envoyer le script » : ses octets suivent. La version est relue hors de la transaction du dépôt : figée, elle ne change plus.
Découvertes : les cartons d'une structure ne sont servis qu'à l'agence ; b2 a besoin d'une route créatrice pour les cartons de sa version figée. Les fichiers déclarés mais jamais envoyés d'un script en cours sont refusés après 24 h par l'effacement, comme ceux d'un dépôt ordinaire : elle les remplace.
