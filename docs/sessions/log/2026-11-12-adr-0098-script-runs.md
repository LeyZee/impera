# 2026-11-12 — ADR 0098 : déroulé de script par fan, socle — in progress
Fait : ADR 0098 écrite acceptée (« ok 0098 », Charles, 12/11 22h28 ; réponses du 12/11 22h21, aucun compteur d'offres) ; domaine pur `agent/domain/script-run.ts` (`applyScriptRunEvent`, `reconcileScriptRun`, `nextScriptStep`, `permittedScripts`, `playedScriptRefs`, `stepPriceCheck`, `scriptStepsHeld`, `platformScriptFaults`) avec ses tests ; contrat `script-runs.ts` ; table `script_runs` (FORCE RLS, migration 0171) et événements `script_step_opened`, `script_step_refused` ; harnais d'isolation RLS ; `createDrizzleScriptRunStore` et son test d'intégration ; glossaire (Déroulé de script, Étape offerte, Étape payante) ; `data-model.md`.
Reste : brancher le déroulé dans `conversation.respond` (sous l'unité de travail de `conversations`, avec les événements `script_*` dans la même transaction, ADR 0007) ; le cerveau qui choisit un script dans la liste permise et lit refus et achat ; le bloc `<script_step>` de la voix (correction de vente 8) ; « /achète » et « /refuse » au playground ; les évals de vente longues (correction 4) ; `listPlatformScripts`, `getScriptHistory` et `sendScriptStep` dans le contrat et le connecteur (P6-01, Bilan ; le domaine lit pour l'instant ses vues `PlatformScriptView` et `ScriptHistoryView`, à renommer sur les types du contrat), la réconciliation avant chaque décision et l'alerte « prix différent » au branchement, et `lastOfferAt` ; `careMode` à brancher sur le mode soin (ADR 0088) ; aligner `script_runs.script_ref` sur l'identité de script que pose la PR #708 de Médias une fois fusionnée.
Décisions : `script_runs` ne tient que l'état de décision, réconcilié avec `getScriptHistory` qui gagne (précise 0018 § 5, Bilan) ; une étape se nomme par `scriptRef` et `stepIndex`, la clé d'idempotence par conversation, script et étape ; sans historique lisible, rien ne se vend ; le délai entre deux scripts part du dernier prix proposé ou du début du dernier déroulé, le teasing compris ; une étape payante d'un déroulé ouvert passe la politique sans le délai (l'escalier monte dans la même session) ; une étape offerte ou un pont avance dès qu'il est parti ; un déroulé fini à ce message le dit une fois (`end` ou `after_refusal`), puis il n'est que de l'historique.
Découvertes : `script_runs`, comme `drafts`, n'a pas de clé étrangère composée (conversation, créatrice) : la RLS empêche d'écrire chez une autre créatrice, mais une ligne de sa créatrice peut nommer la conversation d'une autre ; une seule clé composée sur `conversations` réglerait les deux.
Candidats à suppression : aucun.
Vérifié : pnpm check, pnpm test, tests d'intégration `rls`, `rls-policies` et `script-run-store`.
