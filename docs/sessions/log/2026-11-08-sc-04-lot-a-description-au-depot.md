# 2026-11-08 — SC-04 lot a, chaque média déposé décrit à son arrivée — in_progress

Fait : ADR 0083 acceptée (« ok 0083 ») et fusionnée (#656). Chaque photo et vidéo gardée comme nouveau média de sa médiathèque met en file `content_drops.describe_file` dans la transaction qui la garde. Le job donne au modèle le contexte écrit par le code (catégorie, et pour un script l'étape du carton, sa consigne et la place du média) et un seul média par appel (prompt `sense/creator-drop.md`, d'après celui de Charles : tout décrire, chaque média seul, elle tourne seule, un gode réaliste est un jouet). Le code relit la réponse : renvoi à un autre média redemandé une fois puis gardé en ambre, autre personne, doute ou drapeau gardés avec leur raison (`review_reasons`). Une vidéo de plus de 20 Mo est lue par ses images clés tirées du fichier sur disque, jamais chargée en mémoire. Migration 0141 sur `media_descriptions` (auteur, validation, ressenti de la créatrice, raisons ; une ligne par média et version du prompt). Interrupteur par créatrice (`describeDrops`, éteint par défaut) : rien n'appelle la vision avant qu'on l'allume. Tests : relecture (renvois, paroles citées, autre personne), description (vidéo lourde, conversion, nouvel essai, budget), contexte d'un script, intégration contre MinIO (mis en file une fois, éteint rien, allumé décrit et retenu en ambre, rejoué et redonné rien deux fois).
Pas fait : lot b (étapes et synthèse d'un script), lot c (écran de validation, interrupteur à l'écran, description des médias déjà déposés à l'allumage, redescription quand le prompt change).
Décisions : le job appartient à `content-drops` (il connaît le dépôt et son contexte), la description au module `media` (`createDropDescriptions`) ; budget épuisé, le job se remet d'heure en heure plutôt que d'échouer.
Découvertes : aucune.
