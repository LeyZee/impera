# 2026-11-08 — SC-04 lot b, chaque étape d'un script racontée et sa synthèse — in_progress

Fait : un script envoyé est raconté une fois tous ses médias décrits (ADR 0083 § 6). Le job `content_drops.summarize_script` est mis en file à l'envoi et après chaque description d'un média d'un script envoyé ; il attend le dernier fichier nettoyé et la dernière description, puis donne au rôle `brain` (prompt `brain/script-summary.md`) chaque étape telle que le code la lit dans la version figée (segment, série, carton) avec les descriptions détaillées de ses médias, dans un bloc de données. Le modèle écrit la description générale et le résumé de chaque étape, puis le contexte du tournage ; le code remet les étapes dans l'ordre et refuse une réponse qui ne raconte pas exactement les étapes du script. Aucun prix : une somme ou une devise est redemandée une fois, puis gardée avec la raison `price`. Migration 0145 (`script_drop_summaries`, une ligne par jeu de médias et version du prompt, RLS forcée, lecture seule pour l'équipe, écrite par le job seul). Tests : étapes et séries, ordre et refus de la réponse, prix, attente, interrupteur, budget, intégration Postgres (mis en file à l'envoi, éteint rien, attente de la dernière description, raconté une fois, rejoué rien, rôle applicatif sans écriture).
Pas fait : lot c (écran de validation avec le prix de la grille à côté de chaque étape, colonnes de validation, interrupteur à l'écran avec rattrapage des médias et des scripts, redescription quand le prompt change).
Décisions : le job appartient à `content-drops` (il connaît le script et sa version figée), il lit les descriptions par le module `media` ; la clé d'unicité est le jeu de médias, pas le seul dépôt, pour qu'un emplacement changé redonne une synthèse ; le même interrupteur `describeDrops` couvre les descriptions et les synthèses.
Découvertes : `docs/architecture/jsonb.md` compte encore 24 colonnes `jsonb` quand le schéma en a beaucoup plus ; à recompter dans une PR à part.
