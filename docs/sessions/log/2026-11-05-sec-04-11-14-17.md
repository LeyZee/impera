# 2026-11-05 — Recette SEC-04, SEC-11, SEC-14, SEC-17 : mots de passe trop simples, connexions réussies qui ne bloquent plus, messages de validation en phrases, 401 avant le corps

Fait :
- SEC-04 : un mot de passe d'invitation de 12 espaces, de 12 fois la même lettre ou de moins de 4 caractères distincts est refusé (`isPasswordTooPlain`, `packages/contracts/src/invitation-links.ts`), raison `too_plain`, que la page du lien dit en clair ;
- SEC-11 : une étape de connexion réussie (mot de passe, clé d'accès, code) efface les essais de son compte depuis cette adresse (`forgetCount`, `rate-limit-store.ts`) : là, seuls les refus s'accumulent ; le plafond de 100 toutes adresses n'est jamais effacé (relecture d'Agent) ; la limite par IP de `/v1/auth/*` passe de 20 à 60 par minute ;
- SEC-17 : `POST /v1/auth/two-factor/enable` sans session répond 401 `session_unauthenticated` avant de lire le corps ;
- SEC-14 : les erreurs de champ les plus fréquentes sont des phrases (« Il faut un texte. », « 80 caractères au plus. », « Ce champ est obligatoire. ») ; la locale française de Zod garde les autres (`validation-messages.ts`) ;
- `security.md` décrit les nouvelles limites.

Décisions :
- les essais du mot de passe (`sign-in:<e-mail>`) et ceux du code (`code:<compte>`) restent comptés à part : connaître le mot de passe n'efface jamais les essais de code ;
- l'oubli ne touche que les compteurs Postgres de la production ; un serveur de test sur le magasin en mémoire du plugin garde ses comptes.

Découvertes :
- SEC-03 (un code TOTP rejoué dans sa fenêtre) attend une façon de faire avancer les codes dans les tests : 79 fichiers réutilisent `codeFor()` dans la même fenêtre.

Vérifié :
- unitaire `contracts`, `validation-messages`, `server` ;
- intégration `auth-limits` (douze bonnes connexions d'une adresse, puis dix refus qui bloquent ; le plafond de 100, que les connexions du titulaire n'effacent pas), `second-factor`, `passkey`, `security-settings`, `rate-limit-store`, `invitation-links`.
