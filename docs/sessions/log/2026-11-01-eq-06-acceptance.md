# 2026-11-01 — EQ-06 lot 6a : le prestataire accepte ou conteste, le propriétaire refuse, le délai passé accepte tacitement — in_progress
Fait : quatre routes sous `/v1/payroll/invoices/:invoiceId` (`GET acceptance`, `POST accept`, `POST contest`, `POST contest/refuse`) ; le prestataire seul répond (`invoice_answer_forbidden`), le propriétaire seul refuse une contestation, la même réponse renvoyée rend ce qui est enregistré, une autre est un conflit. Chaque écriture prend le verrou consultatif du document et lit le délai sur l'horloge de la base, celle du déclencheur `keep_invoice_event`. L'émission met en file `payroll.lapse_invoice` pour la fin du délai (acceptation tacite, rien sur un document répondu, remis en file s'il part trop tôt) ; une contestation met en file `payroll.announce_invoice_contest`, qui publie `invoice_contested` une fois par document, sans motif ni nom, et rien pour une contestation déjà tranchée (migration 0047). Relecture de Bilan : 25 essais pour ces deux jobs (environ quatre jours) et un balayage horaire, `payroll.sweep_invoice_acceptance`, qui rattrape un document sans réponse après son délai ou une contestation ouverte sans alerte, quel que soit le sort de leur job.
