# 2026-11-06 — SC-02 b2, le script tourné carton par carton (PWA) — done

Fait : route créatrice `GET /creator-space/content/script-drops/:dropId/cards/:segmentKey[?variant=]`, le SVG d'un carton dessiné depuis la version figée de son dépôt (`scripts.frozenCard`), jamais la bibliothèque courante ; 404 pour un segment absent ou le dépôt d'une autre. Dans la PWA, `/contenu/script/$dropId` : un écran par carton (une série par carton pour une étape à variantes), ses emplacements avec genre, durée et consigne, le genre, le poids et la durée vérifiés sur le téléphone avant tout envoi, chaque fichier déclaré puis envoyé dès qu'il est choisi (« Remplacer », « Reprendre » après un envoi coupé), la progression des médias obligatoires, Précédent/Suivant dans une barre flottante au-dessus de la barre d'onglets, l'aperçu final (pastilles « Prêt » / « À compléter ») et « Envoyer le script ». Contenu : « Commencer » sur une demande de script à version figée, « Continuer » et « Retirer » sur un script en cours. Tests : intégration de la route des cartons ; unitaires du modèle (cartons, progression, lignes) ; écrans (ouverture, refus d'un mauvais genre, remplissage, aperçu incomplet puis complet, envoi).
Pas fait : rappels de l'ADR 0055 § 4 ; `touchesTerm` ; écran d'agence de la cadence.
Décisions : elle reprend au premier carton incomplet, ou à l'aperçu quand tout est là. Un script demandé avant le lot a (sans version figée) se dépose comme avant, par la feuille. Les classes de l'écran prennent le préfixe `sk-` : `sc-` est déjà celui des échanges du planning.
