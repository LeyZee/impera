# Module `scripts`

**Rôle.** Les scripts que la créatrice tourne carton par carton (ADR 0056). L'atelier des **structures** de l'agence, leurs versions, la **file de structures** de chaque créatrice et le rendu des **cartons** (SC-01) ; la **cadence** qui lui demande ses scripts (SC-02 lot a). Viendront le parcours de dépôt (SC-02 lot b), la nomenclature et l'export (SC-03).

**Peut dépendre de.** aucun module métier (feuille). Les limites de la persona lui viennent de `persona` par le composition root (`limitsOf`, sa version active) ; la demande de script est écrite par `content-drops`, branché de même (`requests`, son `scriptRequests`).

**Tables possédées.** `script_structures`, `script_structure_versions`, `script_structure_queue` (migrations 0084 et 0095) et `script_cadences` (migration 0121).

- La bibliothèque (`script_structures`, `script_structure_versions`) appartient à l'agence : hors RLS des créatrices, sous les politiques de l'équipe (`withMember`). Le propriétaire écrit, le propriétaire et les managers actifs lisent, personne d'autre (un chatteur, un compte de créatrice : rien).
- Une version porte le nom, le moment et les segments (`ScriptSegment[]`, relus par le contrat). La dernière version change sur place tant qu'elle n'est pas figée ; une fois figée (`frozen_at`, posée par `structures.freeze` quand une demande la prend, SC-02), un enregistrement écrit la version suivante (règle 6). Un déclencheur refuse toute modification d'une version figée, tout changement de numéro et toute suppression, pour tous les rôles.
- Une structure retirée est archivée (`archived_at`), jamais supprimée ; l'archivage la sort de toutes les files.
- La file (`script_structure_queue`) est par créatrice, sous sa RLS et les mêmes portées (`withTenantMember`) : un compte de la créatrice n'en lit rien. Elle se remplace en entier, sous un verrou par créatrice.

- La cadence (`script_cadences`) est par créatrice, sous sa RLS et les mêmes portées : le propriétaire règle `days` (1 à 90, 14 sans ligne), le propriétaire et les managers actifs lisent ; ce que le job a trouvé (`outcome`, `skipped`, `checked_at`) n'est écrit que par lui, en rôle admin.

**Cadence** (ADR 0056 § 2, `application/ask-scripts.ts`, job horaire `scripts.ask_scripts`). Pour chaque créatrice dont le prochain script tombe dans la semaine (`nextScriptDue`, son jour à elle ; le premier une semaine après le premier passage, chacun des suivants `days` après le précédent ; une cadence en pause repart d'aujourd'hui), `chooseStructure` prend la première structure de sa file qui ne touche aucune limite de sa persona active et nomme celles sautées. La version est figée, relue (une sauvegarde entre la lecture et le gel ne passe pas), demandée (`content_requests` origine `cadence`, `structure_version_id`, une par jour d'échéance), puis sort de la file. Sans persona active : rien (`no_persona`) ; toutes les structures bloquées : rien (`blocked`) ; file vide : la dernière structure redemandée (`reused`), ou rien (`queue_empty`). L'écran de l'agence met en ambre tout ce qui n'est pas `asked`. Rejouable : un passage coupé entre la demande et la file est rattrapé au suivant.

**Règles** (contrat `packages/contracts/src/scripts.ts`, partagé avec l'écran) : `scriptStructureFaults` (au moins une étape ; clés uniques ; une étape a un emplacement ; lettres de variantes uniques, trois au plus ; un pont relie par leurs clés l'étape juste avant lui et celle juste après, un seul pont entre deux étapes) et `scriptSegmentCodes` (numéros dérivés de l'ordre, `E<n>` et `P<n><m>`). Dans le domaine : `disgustBlocks` (une étape qui touche `never_do`, `never_show` ou `disgusts` de sa persona, un pont dont l'accroche touche `never_say` ou `disgusts`, en mots entiers, lu en code), `saveDecision` (règle 6), `queueView`.

**Routes** (montées sous `/v1`, codes d'erreur `SCRIPT_ERROR_CODES`) :

- `GET /script-structures`, `GET /script-structures/:structureId` : propriétaire et opérateurs (la RLS ne montre rien à un chatteur) ;
- `GET /script-structures/starters` : les structures de départ (`SCRIPT_STARTERS`, ADR 0064 § 4), données des contrats, les mêmes pour toute agence ; en dupliquer une, c'est un `POST` de son corps sous un nouvel identifiant ;
- `POST /script-structures` (propriétaire) : écrit la structure et sa version 1 sous l'identifiant du client (201) ; le même envoi rejoue (200) ; le même identifiant avec un autre contenu donne 409 `script_structure_conflict`. Une règle cassée donne 400 avec le message à la place du segment fautif ;
- `PUT /script-structures/:structureId` (propriétaire) : enregistre sur `basedOnVersion` ; 409 `script_structure_stale_conflict` si une autre version a été écrite depuis ; 400 `script_structure_creator_invalid` si la créatrice réservée n'existe pas ou si la structure est déjà dans la file d'une autre ;
- `DELETE /script-structures/:structureId` (propriétaire) : archive (204) ;
- `GET /creators/:creatorId/script-queue` (propriétaire, manager actif) : la file, chaque entrée avec ce qui la bloque aujourd'hui (`blocks`) ; `personaChecked` vaut `false` sans persona active ; tout autre compte reçoit 404 `script_queue_creator_not_found`, que la créatrice existe ou non (recette SEC-06) ;
- `PUT /creators/:creatorId/script-queue` (propriétaire) : remplace la file ; 422 `script_queue_structure_unprocessable` (inconnue, archivée, réservée à une autre) ou 422 `script_queue_disgust_unprocessable` avec, par structure, l'étape et l'entrée de sa persona qui bloquent.

- `GET /creators/:creatorId/script-cadence` (propriétaire, manager actif) et `PUT` (propriétaire, `{ days }`) : la cadence et ce que le job a trouvé la dernière fois (`lastDueOn`, `outcome`, `skipped`, `checkedAt`) ; 404 `script_cadence_creator_not_found` comme pour la file.

- `GET /script-structures/:structureId/cards/:segmentKey?format=card|folder|thumbnail&variant=A|B|C` : le carton d'un segment de la version courante, ou d'une de ses séries. `card` (défaut) rend le SVG pour l'application, `folder` un PNG de 1080 × 1080 pour le dossier, `thumbnail` un PNG de 320 × 320 pour les chatteurs. 404 `script_card_not_found` pour une clé ou une variante absente.
- `POST /script-structures/cards/preview` (propriétaire) : l'aperçu de l'atelier, le carton (`card`) ou la vignette (`thumbnail`) d'un segment d'un brouillon jamais enregistré, toujours en SVG avec les mêmes en-têtes (`no-store`, `default-src 'none'`) ; les segments sont relus un par un, pas contre les règles de structure, pour qu'un brouillon en cours se voie. 404 `script_card_not_found` pour une clé absente.

**Cartons** (`domain/cards.ts`, ADR 0056 § 3 et ADR 0064). Le dessin d'OnlyScript dans la typographie d’Impera : la **couleur du script** (trois tons, `color` de la version) en dégradé sur tout le carton, « ÉTAPE n » et le nom de l'étape au centre, l'intention entre guillemets avec « (GRATUIT) » ou « (PAYANT) » (`access` de l'étape), ce qu'il faut tourner, les indications (trois au moins quand il y en a), l'ambiance, et en pied une pastille par série. En haut, le moment et son icône au trait (soleil, lune, ou les deux pour un script qui passe partout). Une variante a son carton de série (« Série A », sa consigne, les pastilles des séries de l'étape, la sienne pleine) ; un pont dit « PONT n & m », son teaser, toujours « (GRATUIT) », sa photo teasing, et en pied les noms des deux étapes qu'il relie, jointes par une arche en pointillé. La vignette des chatteurs ne garde que l'étape, son nom, ce qu'il faut tourner et « (GRATUIT) » ou « (PAYANT) ». Le code choisit l'encre (claire ou foncée) qui se lit sur les trois tons et leurs mélanges, et le texte est écrit en encre pleine ; une couleur où aucune n'atteint 4,5:1 est refusée à l'enregistrement (`ReadableScriptColorSchema`). Fonction pure : les mêmes octets pour la même entrée. Le texte de l'agence est échappé ; le SVG ne nomme ni fichier, ni image, ni lien, et la route l'envoie avec `Content-Security-Policy: default-src 'none'`. Le PNG est tiré par librsvg (`infra/card-rasterizer.ts`, aucune dépendance npm) : `rsvg-convert` dans l'image Docker, où l'ffmpeg d'Alpine n'a pas de décodeur librsvg, sinon le décodeur librsvg d'ffmpeg (poste de dev et CI), choisi une fois par processus, avec une configuration de polices qui ne nomme que `infra/fonts/` (Geist et Instrument Serif en TTF, SIL OFL 1.1, licences à côté) : le même SVG donne le même PNG dans une même image Docker (une autre version de librsvg, pango ou freetype peut changer l'anticrénelage, on ne compare donc jamais un PNG d'une machine à l'autre). Deux rendus au plus tournent en même temps. L'image Docker copie ce dossier comme celui des factures, et sa construction échoue si `rsvg-convert` n'y tire pas un SVG.

Chaque écriture ajoute une ligne `script_structure.create`, `.update`, `.archive`, `.freeze` (sans compte quand le job fige), `script_queue.update` ou `script_cadence.update` dans `audit_log`.

## Structure

- `domain/` : limites de la persona, décision d'enregistrement, vue de la file, cartons, ports `ScriptStructureStore` et `RasterizeCard`. Zéro I/O.
- `application/` : le job de la cadence.
- `infra/db/` : les tables, chaque ligne relue par le contrat.
- `infra/http/` : les routes.
- `infra/card-rasterizer.ts` et `infra/fonts/` : le PNG d'un carton.
